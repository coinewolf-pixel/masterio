# Известные ограничения и риски (после фазы 7)

## Что ещё не сделано (по плану фаз)

- **Приглашение в команду без SMS.** Twilio Verify отправляет только коды входа, поэтому приглашение не приходит по SMS: руководитель сообщает человеку, что нужно установить Masterio Pro и войти с этим номером, — приглашение ждёт его в приложении. Если у человека уже есть аккаунт мастера, он получает push.
- **Участник команды — отдельный аккаунт мастера.** Пока он в команде, его собственные линия, предложения и пополнение выключены; деньги на его кошельке не трогаются и снова доступны после выхода из команды. Руководитель своей команды с участниками не может вступить в чужую.
- **«Пришёл другой человек»** определяет клиент (кнопка в заказе). Автоматически по геопозиции это не распознаётся: телефон назначенного участника может быть у другого человека. Сигнал клиента сразу останавливает заказ и открывает спор.
- **Страховка участника**: подходит его собственный действующий полис с нужными рисками; у компании (тип COMPANY) — также полис компании. Как именно полис компании покрывает сотрудников в конкретной стране, должен подтвердить юрист — правило настраивается в «Правилах страхования».
- **Деньги в споре.** Masterio не держит деньги клиента (оплата наличными мастеру), поэтому решение спора может вернуть мастеру только удержанную комиссию (проводка REVERSAL, не больше удержанного). Возврат денег клиенту — договорённость сторон, которую поддержка фиксирует в итоге спора, а не перевод платформы.
- **Тексты юридических документов** в систему вносит админ: публикация невозможна без всех 5 языков и имени проверившего юриста. Шаблонов договоров в архиве нет намеренно — тексты должен подготовить юрист для каждой страны.
- **Подтверждение страховки** — это проверка модератором фото полиса, срока и рисков. Платформа не связывается со страховой и не гарантирует покрытие конкретного случая (это написано мастеру на экране).
- **Сверка со Stripe** (ежедневная) — вместе с карточными оплатами; сейчас есть проверка, что журнал проводок сходится.
- **Поиск людей в CRM** — по телефону или ID: имена хранятся зашифрованными и поиску не поддаются.
- **Оплата картой в Masterio** скрыта, пока флаг `CARD_PAYMENTS_ENABLED` выключен (раздел 22); экран оплаты картой будет добавлен вместе с её включением.
- **Выбор точного времени** заказа сделан кнопками «через 2/4/24/48 ч» (округление до 15 минут); календарь с произвольной датой — по отзывам пользователей.
- **Удаление аккаунта** анонимизирует пользователя сразу. Данные, которые закон требует хранить (журнал проводок, платежи, споры и их доказательства — `EVIDENCE_RETENTION_DAYS`), остаются без имени и контактов; список сохранённого возвращается пользователю. Окончательная очистка таких записей по истечении срока — отдельная задача перед запуском, сроки подтверждает юрист.
- **Карточные оплаты клиентов и выплаты Stripe Connect** выключены флагами (раздел 22) и будут написаны перед их включением.

## Риски

- **Часовой пояс базы данных.** Колонки времени хранят UTC. Сервер теперь сам задаёт `TimeZone=UTC` для каждого соединения — раньше на базе с другим часовым поясом время событий и проверка «свежей» геопозиции сдвигались (найдено при проверке CRM, закрыто тестом).
- **Подложка карты CRM.** Публичные тайлы OpenStreetMap нельзя использовать под нагрузкой — в продакшене нужен ключ MapTiler/Stadia (`VITE_MAP_TILE_URL`).

- **Юридические:** невозвратное пополнение, наличные расчёты, налоги и требования AML различаются по странам. До запуска в каждой стране нужна проверка юристом и бухгалтером (разделы 18.6, 21.2, 21.8).
- **Скрытые наличные заказы:** мастер может договориться с клиентом и отменить заказ. Защита — подтверждение суммы клиентом, GPS-трек, отметки подозрительных отмен, лимит долга. Полностью исключить это при оплате наличными нельзя.
- **Фоновая геопозиция на iOS** ограничивается системой: при агрессивной экономии батареи точки могут приходить реже. Сервер показывает клиенту «связь потеряна» через 60 секунд без точек.
- **Push не гарантирует доставку.** Предложение заказа дублируется событием Socket.IO, а время предложения решает сервер.
- **Один номер — одна роль:** клиенту, который хочет стать мастером, нужен второй номер.
- **Railway Redis** должен хранить данные на диске: без этого при перезапуске Redis таймеры будут восстановлены из базы (функция `recover`), но с задержкой до перезапуска API.
- **ETA без ключа Google** считается по прямой с поправкой на маршрут — это грубая оценка.
- **Карта Masterio на Android без ключа Maps SDK** не показывает подложку (метки и линии есть); на iOS без ключа используется Apple Maps. Поиск адресов без серверного ключа отключён — остаются GPS и выбор на карте.
- **Плавность метки** зависит от частоты точек мастера (около 5 с на активном заказе); между точками метка движется по прямой, а не по дорогам.

## Что не проверено на настоящем телефоне

Masterio проверено так же: строгие типы, линтер, 21 тест логики (плавное движение и поворот метки, кадр карты, ETA, выбор города заказа, форматирование, полнота переводов и текстов разрешений), сборка JS-бандлов Android и iOS и `expo prebuild` (ключ Google Maps в манифесте, фоновая геопозиция запрещена, тексты разрешений на 5 языках). Живую карту на двух реальных телефонах пройдите по разделу «Masterio на телефоне» в `CHECKLIST.md`.


Приложение Masterio Pro проверено так: строгая проверка типов, линтер, 25 тестов логики (обновление токенов, буфер геопозиции, отсчёт по серверному времени, полнота переводов), успешная сборка JS-бандлов Android и iOS и успешный `expo prebuild` (генерация нативных проектов со всеми разрешениями и переводами системных текстов). Собрать APK и запустить на устройстве здесь нельзя: нет Android SDK, Xcode и телефона. Перед выпуском пройдите раздел «Masterio Pro на телефоне» в `CHECKLIST.md` на реальных Android и iPhone — особенно фоновую геопозицию и push.

## Проверка окружения

Движок миграций Prisma для проверок здесь собирался из исходников, потому что в рабочей среде нет доступа к серверу бинарников Prisma. На Railway и в GitHub Actions Prisma скачивает движок сама — ничего делать не нужно. Docker-образ здесь не собирался (нет Docker-демона); CI собирает API командой `pnpm build`.
