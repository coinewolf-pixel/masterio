# Masterio API (`apps/api`)

NestJS 11, Prisma 7 (без бинарного движка, через `@prisma/adapter-pg`), PostgreSQL 16 + PostGIS, Redis 7 + BullMQ, Socket.IO.

> Для сборки нужен общий пакет из `masterio-shared-phase-7.zip`, распакованный в `packages/shared` рядом с `apps/api`
> (см. корневой README). Без него `@masterio/shared` не найдётся.

## Что умеет сервер (фазы 2–7)

- Вход по SMS-коду (Twilio Verify), JWT access + refresh с ротацией и защитой от повторного использования, вход админов по паролю и TOTP.
- Лимиты: SMS по телефону, устройству и IP; попытки ввода кода; общие лимиты API.
- Категории (20, названия на 5 языках) и города, проверка «есть ли мастера рядом».
- Заказ с адресом (PostGIS), рассылка **по одному мастеру на 30 секунд**, круги, отказы, `BATCH_SIZE`, восстановление таймеров после перезапуска, атомарное принятие.
- Статусы «Выехал», «Прибыл» (только в геозоне), «Начал работу», смета и её подтверждение клиентом.
- Живое отслеживание по Socket.IO: позиция, расстояние, ETA, «мастер рядом», «связь потеряна», трек хранится ограниченное время.
- Наличные: «получил X» и «оплатил X», расхождение — автоматический спор, автоподтверждение по таймеру.
- Деньги: журнал операций с двойной записью (БД запрещает правку), карманы мастера, комиссия 20% с порядком списания бонус → приветственный → пополнение → долг, приветственный кредит 50/100 с лимитами и вторым админом, пополнение через Stripe с webhooks.
- Отмены со штрафами и компенсацией, счётчики отмен, фильтр чата, отметки подозрительных действий.
- Настройки и флаги без релиза (действуют сразу во всех инстансах), журнал действий админов.
- CRM API (фаза 5): сводка, живая карта, заказы, люди, документы, финансы и сверка журнала, настройки с историей, справочники, админы с подролями.
- Фаза 6: единый процесс споров со снимками материалов и возвратом комиссии, «клиент не вышел», происшествия, поддержка, юридические документы с версиями и согласиями, правила страхования по странам и сроки документов, GDPR-выгрузка и удаление, месячный расчёт бонусов с одобрением finance.
- Фаза 7: команды — приглашения по номеру, режим участника, назначение только проверенного участника (личность, лицензия, страховка, занятость), замена с согласием клиента, автоназначение по таймеру, ёмкость команды, «пришёл другой человек» с автоматическим спором, журнал команды (только дописывается).

## Команды

```bash
pnpm dev             # запуск из исходников
pnpm build           # prisma generate + сборка в dist/
pnpm start:prod      # миграции + запуск собранного сервера
pnpm prisma:deploy   # применить миграции
pnpm seed            # категории, города, ступени бонусов, первый superadmin
pnpm typecheck && pnpm lint && pnpm test
```

Переменные окружения описаны в `.env.example`.

## Деплой на Railway

1. Создайте проект и добавьте **PostgreSQL с PostGIS** (шаблон PostGIS в Railway или любой Postgres-образ с PostGIS 3) и **Redis**. В Redis включите сохранение на диск, чтобы таймеры предложений переживали перезапуск.
2. Подключите репозиторий monorepo. В корне лежит `railway.json`: сборка по `apps/api/Dockerfile`, healthcheck `/api/v1/health`.
3. В переменных сервиса API задайте значения из `.env.example`: `DATABASE_URL`, `REDIS_URL` (ссылки на сервисы Railway), `JWT_ACCESS_SECRET`, `PII_ENCRYPTION_KEY`, `NODE_ENV=production`, `SMS_PROVIDER=twilio` + ключи Twilio, `PUSH_PROVIDER=fcm` + `FIREBASE_SERVICE_ACCOUNT_B64`, ключи Stripe, `CORS_ORIGINS` (адрес админки).
4. При старте контейнер сам применяет миграции (`prisma migrate deploy`).
5. Один раз выполните seed: `railway run pnpm --filter @masterio/api seed` с заданными `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD`. Ссылку для приложения-аутентификатора (TOTP) seed печатает один раз.
6. В Stripe добавьте webhook на `https://<домен>/api/v1/webhooks/stripe` с событиями `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.dispute.created`.

При росте нагрузки можно запустить второй сервис из того же образа с `QUEUE_WORKERS_ENABLED=true`, а у основного поставить `false`: очереди и Socket.IO работают через Redis, инстансы не мешают друг другу.

## Socket.IO

Namespace `/rt`, токен в `auth.token`. После проверки токена сервер шлёт `rt:ready` — только после него клиент отправляет события. Имена событий и данные — в `@masterio/shared` (`RT_EVENTS`).
